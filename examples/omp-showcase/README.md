# `omp-showcase` — the generated open.mp wrappers on a real server

Not a template to copy: a test harness. Every function under `samp::omp` that
wraps an open.mp interface is generated from the SDK headers
(`cargo xtask gen-omp`), and every slot the official binaries expose is
checked by `cargo xtask check-abi --generated`. What neither can see is
whether a call *works* — the argument types, the return convention, the stack
the callee cleans under `thiscall`. This plugin runs the calls.

## What it does

Once every component is ready (`on_omp_ready`), it:

- creates one entity of each kind the server offers — object, pickup, vehicle,
  textdraw, gang zone, actor, 3D text label, menu, player class — and checks
  what came back;
- connects an NPC, so the player-side wrappers run against a real `IPlayer`,
  including the per-player extensions (`player_objects`, `player_menus`, …);
- round-trips every setter that has a matching getter: set a value different
  from the current one, read it back, restore the original. These checks live
  in `src/round_trips.rs`, generated by `cargo xtask roundtrip`;
- registers generated event handlers on the server's dispatchers and has the
  server fire them: an NPC's create, spawn, death and destroy — each at a
  different depth of its vtable — and an object's `onMoved`;
- re-runs the setters the first pass saw ignored under the conditions they
  need (an NPC seated in a vehicle, for instance), so an ignore the server
  explains is told apart from one it does not.

## Reading the result

The log ends with one line:

```
[showcase] 75 passed, N ignored by the setter (M of them proven under valid conditions), 0 wrong
```

- **passed** — both slots and both types are right.
- **ignored** — the value did not change. Sometimes the server's own rule,
  sometimes a wrong slot; each one is listed so a person decides.
- **wrong** — a wrong slot or type. Must be `0`.

On Windows a wrong argument size ends the process instead of returning a wrong
value. Each call is announced at `debug` level first, so the last `>` line in
the log names the call that did it.

## Running it

Load it as a native component on open.mp — on Linux and on Windows. The server
needs `max_bots` above zero in `config.json` for the NPC. Both runs should
report `0 wrong` with the same counts.

```sh
cargo build --release --target i686-unknown-linux-gnu -p omp-showcase
cargo xwin build --release --xwin-arch x86 --target i686-pc-windows-msvc -p omp-showcase
```

Copy the library into the server's `components/` directory. Run it after
regenerating the wrappers or the round trips; see
[Talking to the Open Multiplayer Server Directly](../../docs/omp-interfaces.md).
